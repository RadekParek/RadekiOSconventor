# compat-runtime-v1 architecture

`compat-runtime-v1` is an experimental Android runtime for a user's own authorized 32-bit iPhone OS 2–6 application packages. The product goal is static recompilation to native ARM64 as the primary CPU strategy, backed by iOS compatibility shims; the pinned ARM32 backend is a narrow fallback for code that is not yet covered by the recompiler. This runtime work is not a general iOS implementation and does not claim game compatibility without repeatable smoke evidence.

The Android library does not bundle the input IPA or Apple executable. The runtime must not draw technical messages, banners, watermarks, or diagnostic overlays while guest code is running.

## Runtime path

1. **User-selected input.** `RuntimeBridge` reads the user's selected URI or a caller-owned stream. The caller supplies the main-executable archive entry resolved from bundle metadata, `Payload/<App>.app/<CFBundleExecutable>`. The importer retains only that bounded entry in memory; it does not persist the IPA or extract the application tree into the runtime artifact.
2. **Authorization and input policy.** JNI requires explicit authorization confirmation, rejects empty or oversized input, and returns a blocked report on invalid input. The Mach-O loader rejects a non-zero `cryptid`. No FairPlay decryption or protection removal is attempted.
3. **32-bit guest address space and loader.** `GuestAddressSpace` provides bounded mappings, permissions, heap allocations, and checked guest pointers. `MachOLoader` selects a supported 32-bit ARM slice, reads the available legacy entry-point metadata, maps segments, and applies supported bind, rebase, external-relocation, and indirect-symbol fixups. Darwin imports resolve only through exact registered native adapters. Unsupported structures and unresolved imports fail closed.
4. **Objective-C runtime core.** `objc_runtime` and `objc_shims` host-test a deliberately small object/dispatch subset: selector/class/protocol lookup, `respondsToSelector:`, class-membership and protocol-conformance queries against registered guest metadata, selected message-send variants, imported class-data materialization, retain-style property storage, and autorelease-pool operations. The loader initializer now has bounded registration for 32-bit app class/metaclass, superclass, ivar, method, and category metadata. A synthetic Mach-O verifies class registration, allocation, method dispatch, and guest IMP execution through pinned Dynarmic; this does not establish Angry Birds' real class metadata or general Foundation/UIKit ABI compatibility. Static reconstruction identifies Angry Birds' `AppController : NSObject` and `MyEAGLView : UIView` through external-relocation symbols. The current provider pass removes import-registration blocking for the observed 254-symbol fixture, but explicit runtime boundaries and unimplemented framework behavior still prevent a gameplay claim.
5. **ARM32 execution backend.** `GuestRunner` uses the shared `CpuBackend` and `ShimRegistry` callout contract. The pinned Dynarmic A32 JIT ARM32 backend has a host integration test where synthetic guest code calls a registered import adapter and returns. The current Angry Birds fixture registers all 181 same-name NDK and 73 Darwin-only catalog entries before loading; an import outside those catalogs or an explicit ABI boundary still stops safely. This proves a host backend/callout path only; Android/JNI compilation and on-device execution have not been established.
6. **Evidence and smoke results.** Loader, CPU, execution, and exact import outcomes are returned as structured reports. A loader's first unresolved symbol is an ordering result, not a runtime call trace. `menu` and `playable` are recorded only after repeatable smoke evidence in `compatibility/database.json`.

## Current real-IPA evidence (2026-10-05)

The authorized `tests/data/AngryBirds_v1.0_os30.ipa` has been statically analyzed. The analysis output is ignored local data, not a release artifact. The native loader's image initializer now registers the actual `AppController : NSObject` (44-byte instance, 9 ivars) and `MyEAGLView : UIView` (72-byte instance, 9 ivars). A host harness allocates `MyEAGLView`; `_objc_msgSend` reports its `createFramebuffer` selector present, an absent selector missing, `isKindOfClass:UIView` true, and `isMemberOfClass:MyEAGLView` true, then selects guest IMP `0x69610` without executing its body. Static Objective-C metadata declares its `context` property retain/non-atomic (`T@\"EAGLContext\",&,N,Vcontext`), matching the narrow `_objc_setProperty` retain path; this is not execution evidence. The app image declares three protocols and no categories; loader registration and host dispatch confirm `AppController` conforms to `UIApplicationDelegate`, `UIAccelerometerDelegate`, and inherited `NSObject`, while an unknown protocol lookup returns null. The analyzer decoded 31.49% of the ARMv6 `__text` section, so import rankings and callsites remain partial static evidence.

The historical host loader probe mapped the 1,822,112-byte ARMv6 main executable and stopped with `BLOCKED_UNRESOLVED_IMPORTS` before the full provider catalog existed. That result is retained as historical evidence, not the current registration result. The current runtime registers all 181 same-name NDK entries through specialized or bounded ARM32 adapters and all 73 Darwin-only entries through typed compatibility providers. It also registers the broader 1,229-name reviewed NDK inventory: known signatures use typed adapters, while the remaining Android framework/driver signatures use explicitly named bounded providers. Both NDK catalogs and the Darwin catalog are checked before loading; any missing binding fails closed. The adapters still do not provide full Foundation/UIKit/OpenAL behavior, device audio, guest catch/landing-pad transfer, or proof that Angry Birds reaches a frame or menu.
Static `_main` reconstruction first sees `_objc_msgSend` at `0x74378` with class reference `_OBJC_CLASS_$_NSAutoreleasePool` and selector `new`; it next sees `_UIApplicationMain` at `0x74390`. That is recovered register-flow evidence, not an execution trace. The full evidence, rankings, dependency attribution, and uncertainty notes are in [`docs/ANGRY_BIRDS_V1_FINDINGS.md`](../../docs/ANGRY_BIRDS_V1_FINDINGS.md).

## Boundaries and current implementation state

- The Objective-C registry is no longer empty, but its host-tested adapters remain a narrow subset. Imported class-object resolution proves guest-data materialization only; it does not provide those Apple frameworks' behavior.
- The current loader does not implement all dyld behavior, arbitrary dependent Mach-O loading, all relocation forms, or complete Objective-C/C++ exception/unwind semantics. Bounded Objective-C image-initializer registration is tested against the real IPA's classes and ivars, but broad initializer execution and application-method execution are not established. Unsupported or unresolved inputs remain blocked.
- `_objc_enumerationMutation` now resolves to a fail-closed guest-exception boundary tested through pinned Dynarmic. It stops with `GUEST_EXCEPTION_RAISED`; Objective-C catch handling and ARM32 SJLJ unwind are still not implemented. A state-only `_AudioSessionInitialize`/`_AudioSessionSetActive` pair supplies no audio output or interruption delivery; the old `_AudioSessionSetActive` first-missing result is historical and the current blocker is framework/game execution evidence.
- Offline static reconstruction and runtime class registration remain distinct evidence. The real IPA's class names, superclass links, instance sizes, and ivar names now register; selector dispatch selects a guest IMP in a host probe. No Angry Birds method body has executed.
- The compatibility smoke database has no app smoke records. Angry Birds is analyzed and loader-probed, not launched on an Android device. Its import rankings inform shim priorities but are not a smoke result or a claim that any shim unblocked a game.
- Java/Javac/`JAVA_HOME` are unavailable in this environment. Android Gradle, JNI/NDK linkage, device import behavior, first-frame/menu behavior, and Android host/app parity are therefore not established.

## Next shim families

Priorities are informed by the recovered Angry Birds imports and startup evidence; none is claimed to unblock the title yet.

1. **Objective-C runtime and metadata:** extend and harden app-class, ivar, method, category, and selector coverage; add full guest exception/catch plus ARM32 SJLJ unwind behavior for `_objc_enumerationMutation`. Protocol lookup/conformance and retain/copy property paths are host-tested against the real IPA's declarations.
2. **Foundation/CoreFoundation startup:** implement only observed bundle/resource, object, constant-string, collection, and run-loop behavior needed to test startup and the first frame.
3. **Guest execution integration:** connect the bounded provider set to complete guest callsite/relocation execution, add a scheduler for pthread callbacks, and validate the first frame/menu on an Android device. The C++ ABI adapter covers the bounded allocation/guard/RTTI boundary; do not alias `libstdc++` or `libgcc_s` wholesale.

UIKit/CoreGraphics/CoreAnimation rendering and input remain subsequent work, and cannot be treated as supported based on Android name matches or class-data pointers.

## Build and test

The native host suite exercises guest memory and pointer bounds, Mach-O/FAT selection, entry points, supported dyld fixups, exact shim lookup, unresolved-import reports, Objective-C runtime behavior, and the shared CPU/callout contract. With the pinned Dynarmic backend enabled, it additionally runs synthetic ARM/Thumb fixtures. Host tests do not prove Android compatibility or run the real IPA.

The Android library is built through `:compat-runtime-v1:assembleDebug` or `assembleRelease`; it explicitly builds/packages both the `compat_runtime_v1` and shared `unicorn` CMake targets for the ARM64 Android ABI. The resulting `libcompat_runtime_v1.so` has a `DT_NEEDED` dependency on `statically linked dynarmic`; both must ship together in generated game-runtime APKs. The stable host-side report artifact name is `compat-runtime-v1-report.json`. A successful library build alone would still not establish a real-game smoke result.
